# TaskFlow

**Веб-сервис управления личными задачами с интеллектуальной системой приоритизации**

TaskFlow — учебный full-stack проект, предназначенный для управления личными задачами. Приложение позволяет создавать задачи, редактировать их, отслеживать выполнение и автоматически рассчитывать приоритет на основе срока выполнения, важности и текущего статуса.

## Возможности

- Регистрация и авторизация пользователей.
- Аутентификация с использованием JWT.
- Создание, просмотр, редактирование и удаление задач.
- Поиск и фильтрация задач.
- Сортировка задач.
- Управление статусами выполнения.
- Автоматический расчёт приоритета задач.
- Просмотр статистики по задачам.

## Система приоритизации

Приоритет задачи рассчитывается по совокупности нескольких факторов:

- **Срок выполнения:** чем ближе дедлайн или чем сильнее он просрочен, тем выше приоритет.
- **Важность:** учитывается установленный пользователем уровень важности.
- **Статус:** учитывается текущее состояние задачи.

Итоговый балл ограничивается значением 100. Для расчёта используется алгоритм на основе заданных правил и весов. Это позволяет объяснить результат приоритизации и изменять логику расчёта без использования машинного обучения.

## Запуск проекта

### 1. Клонирование репозитория

```bash
git clone https://github.com/wavemale/taskflow.git
cd taskflow
```

### 2. Настройка PostgreSQL

Создайте базу данных:

```sql
CREATE DATABASE taskflow;
```

Убедитесь, что PostgreSQL запущен и доступен на порту `5432`.

### 3. Настройка переменных окружения

Backend использует следующие переменные:

| Переменная | Назначение |
|---|---|
| `DB_URL` | JDBC-адрес базы данных |
| `DB_USERNAME` | Пользователь PostgreSQL |
| `DB_PASSWORD` | Пароль PostgreSQL |
| `JWT_SECRET` | Секретный ключ для подписи JWT |

Пример значений для локального запуска в PowerShell:

```powershell
$env:DB_URL="jdbc:postgresql://localhost:5432/taskflow"
$env:DB_USERNAME="postgres"
$env:DB_PASSWORD="your_database_password"
$env:JWT_SECRET="replace_with_a_long_random_secret_key"
```

Используйте собственный пароль базы данных и случайный секретный ключ длиной не менее 32 байт. Не публикуйте реальные значения в репозитории.

### 4. Запуск backend

Из корневой папки проекта выполните:

```powershell
.\mvnw.cmd spring-boot:run
```

Backend запускается по адресу:

```text
http://localhost:8080
```

### 5. Запуск frontend

Откройте второй терминал:

```powershell
cd frontend
npm install
npm run dev
```

Vite обычно запускает frontend по адресу:

```text
http://localhost:5173
```

Если адрес API в frontend задан явно, убедитесь, что он указывает на локальный backend `http://localhost:8080`.

## API

Основные endpoints backend:

| Метод | Endpoint | Назначение |
|---|---|---|
| POST | `/auth/register` | Регистрация |
| POST | `/auth/login` | Авторизация |
| POST | `/tasks` | Создание задачи |
| GET | `/tasks` | Получение списка задач |
| GET | `/tasks/statistics` | Получение статистики |
| GET | `/tasks/{id}` | Получение задачи |
| PUT | `/tasks/{id}` | Обновление задачи |
| DELETE | `/tasks/{id}` | Удаление задачи |

Для защищённых endpoints требуется JWT в заголовке `Authorization`:

```text
Authorization: Bearer <token>
```

Документация API через Swagger UI доступна по адресу:

```text
http://localhost:8080/swagger-ui/index.html
```
